## Starting contract and inspected facts

The final [A contract](2026-10-30-evidence-contract.md) sets three distinct admission boundaries: normalized compact application bundle **12,288 UTF-8 bytes**, normalized application contribution **60,000 bytes**, SQL bundle **16,384 bytes of `jsonb::text`**. The earlier 20 KB shorthand is superseded. None bounds report lifetime output. [Rowan (MCP engineer)'s review](2026-10-30-agent-output-budget.md) already identifies that aggregate growth predates A.

Static source inspection: `app/api/mcp/route.ts` returns both `content[0].text = JSON.stringify(data)` and `structuredContent: data`; `lib/mcp-evidence.ts` retains raw prose, all fixes/results and optional bundles. These are source facts at inspection, not deployed or stored-roundtrip evidence. No SDK install, network harness, product request or model call was performed.

**Inference from the transport rule plus inspected source:** measure the decompressed complete JSON response body/event, including text, structured content, JSON escaping and protocol envelope. Measuring only raw report JSON understates that boundary. This does not establish that both copies count twice against a model's tokens: client transformation must be observed separately. Compression cannot be assumed to evade a decompressed-size ceiling.

Rowan (MCP engineer)'s illustrative pre-cap total of 7,429,932 bytes is below 16,777,216 bytes (16 MiB); it is neither a failing response nor a maximum. Do not convert that scenario into an incident, an operator need or a current-client compatibility pass. The per-record ceilings cannot guarantee that an unbounded aggregate remains under a finite ceiling.

## Decision and falsifier

**Change the acceptance claim now, not A's architecture:** distinguish (1) export/parity, (2) actual client's delivery or file recovery, (3) applicable evidence use in the chosen next action, and (4) later availability if the task depends on it. Existing SDK checks establish only their stated layer. Large-output file persistence alone is not evidence loss if the client can recover the needed records; a warning alone is not failure. A correct conditional retest may cite conflicting Failed evidence, as the [PM plan](../plan.md) already requires.

For the next already-authorized changed-artifact task, record client/version, negotiated protocol, relevant nonsecret output settings, report/fix/result counts, complete decompressed response bytes, and whether the client delivered inline, persisted, truncated or failed. If sizing is unavailable, say unknown. Use the agreed labeled fixture with an applicable Failed observation and explicit null/unknown fields; record which source/result the chosen action actually used. No real operator benefit follows from a synthetic pass.

**Measured technical escalation trigger:** a reproducible authorized report succeeds through the raw read path yet the named client rejects the measured full response, or cannot recover a materially required record after persistence/truncation. Retain the exact artifact and sanitized failure signature, not private transcripts. A measured result above the documented ceiling makes that client's unbounded-support promise untenable; a documented ceiling alone is not a measured Token Overflow failure. Rowan (MCP engineer)/Rafael (Engineering lead) then evaluate the smallest separately reviewed remedy. Pagination remains one possible later proposal, not a predetermined fix.

**Consumption falsifier:** the client retrieves enough data but ignores/overrides a materially applicable Failed observation, treats null as known/passed, or claims an unconditional cure. Record this as a decision/visibility failure at the observed layer, not automatically a transport defect. If required evidence is recovered and informs the bounded action, that fixture/client passes; it does not establish arbitrary-size usability or future retention. If no changed decision or discriminating information results, retain no added information.

Uncertainty: no installed-client implementation was audited here; no effective client settings or token counts were inspected; no aggregate production corpus, recovery path or contextual retention was tested. No actionable observed-failure trigger currently exists. The actionable result is a precise acceptance boundary and a source-backed threshold to investigate when relevant evidence arrives.
