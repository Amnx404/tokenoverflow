## Event meanings and privacy

| Event | Meaning / safe fields | Interpretation limit |
| --- | --- | --- |
| `to_page_view` | Known page template, optional bounded `initial_observer_commit` / `navigation_route_commit` duration | Root observer/route-context commit can precede streamed content readiness. Neither proves full hydration, usable search, LCP/TTFB, a session or a unique visitor. Same-path search/filter/example/page changes trigger through query object identity without serialization. |
| `to_ui_action` | Fixed navigation, search/contribution/key/sign-in submit intent, clipboard success or `feedback_open_intent`; optional known target template | Submit/click is intent, not a successful contribution, completed read or confirmed chooser open. Copy fires only after clipboard success and sends no value. |
| `to_browser_error` | Known page and fixed unhandled-error/rejection code | No message, filename, reason, stack, exception or prompt is collected. |
| `to_server_render_error` | Known page, render/action type and fixed internal-error code | Framework hook ignores error/digest/headers and does not duplicate API operation failures. Its generated UUID is diagnostic, not a preexisting response span. |
| `to_operation_completed` | Fixed REST/tRPC/MCP route/operation, status, bounded latency, generated request UUID and logical-operation/transport scope | Exactly one terminal sample per span. 2xx/3xx success, 4xx expected rejection, 5xx failure. Transport HTTP 200 can contain a logically failed MCP tool; do not sum both as one task denominator. SDK rejections before tool callbacks appear only in transport scope. |
| `to_auth_outcome` | Fixed email signup/signin, confirmation, auth callback or signout stage; fixed `auth_status`, bounded duration, server release/environment/traffic and a generated event UUID | No HTTP status or generic operation outcome. Neutral signup prompt is not account creation or delivered mail; returned session is not fresh server verification; resolved signout call is not independently verified revocation. |

Auth stages deliberately preserve the existing branches: duplicate-account signup codes and signup without a session both emit `neutral_confirmation_prompt`; weak password/invalid input emit `input_rejected`, existing exact rate codes `rate_limited`, actual SDK provider errors `provider_rejected`, missing/rejected fresh-user checks `session_unverified` and thrown client/provider calls `unavailable`. Only the existing successful fresh `getUser()` branches emit `server_session_verified`. Callback/confirmation with the existing returned session emit `session_returned`; they do not add a user lookup. A resolved signout call emits `signout_returned` even when its currently ignored result contains an error; a thrown value is recorded as unavailable and rethrown unchanged. Callback query error presence remains `input_rejected`: it is caller input, not proof of a provider rejection. GitHub-start remains uninstrumented. Each helper accepts only fixed operation/status categories, reads only the synthetic marker before delivery, and records once; disabled capture reads no headers or SDK. No form fields, auth objects, provider codes/messages, redirect URLs or supplied request IDs enter the helper. Generated UUIDs identify individual stages, with no cross-stage identity join or conversion funnel.

All captured events get server-stamped release, environment and `synthetic`/`unclassified` traffic class. Health is always synthetic. Nonproduction is synthetic; controlled browser automation and `X-TokenOverflow-Synthetic: 1` can only mark synthetic, never prove a real operator. An unlabeled public request is **unclassified**, never adoption. Client-provided IDs/releases are not accepted. The existing eight-field console failure schema and response request-ID behavior remain; successful requests become PostHog samples without adding success console logs.

The browser uses no PostHog JS SDK, storage, cookies or persistent identity. Manual events go to a fixed first-party endpoint with no credentials/referrer; DNT/GPC suppress them. The collector requires a known host and matching Origin, strict event-specific schemas, at most 1,536 streamed bytes and a one-second read deadline; it never forwards raw browser objects, headers, IPs, user agents or cookies. It excludes itself from instrumentation. It is not an arbitrary proxy/destination. Raw searches/full URLs/query/hash, DOM/form/clipboard text, prompts, sessions, customer data, account/key/report identifiers, SQL/parameters and raw errors are excluded.

Pinned `posthog-node@5.61.1` receives reconstructed safe fields, generated per-event distinct IDs and `$process_person_profile:false`; GeoIP, automatic exceptions and local feature evaluation are disabled. No identify/alias/groups, replay, broad autocapture, surveys, logs/trace auto-instrumentation or feature flags are enabled. A final SDK property allowlist prevents injected context/defaults from expanding the payload. Distinct IDs are random event identifiers and must never be counted as people. There is deliberately no cross-chat/session funnel or identity join.

## Delivery and acceptance

`next/server.after()` schedules delivery after response completion; application status/body do not await PostHog. The SDK value loads only inside enabled, nonempty delivery, not on disabled/precallback request paths. The application queue holds at most 100 records, at most two batches per lifecycle; the SDK queue holds at most 100. There is no automatic SDK flush timer/threshold. Individual requests have a one-second timeout with zero SDK network retries; an independent two-second deadline bounds each batch's overall wait. That race does **not** cancel the underlying SDK attempt. On timeout, the queue drops pending/new events and permits no new underlying delivery until the one pending attempt settles; if it never settles, this instance's telemetry remains suspended/dropped. Late rejection is handled silently. Explicit `flush()` uses a reusable client: this pinned SDK's `shutdown()` logs raw failure response bodies internally, so it is not called per request. A network-failed bounded SDK queue may retry on a later lifecycle. Failed/missing lifecycle scheduling drops data. Browser attempts cap at 30/minute; collector/server caps are 120/minute per instance. These are best-effort samples, not durable, complete, globally rate-limited or exactly-once telemetry. Platform termination, blockers, opt-out, caps and outages can lose observations.
