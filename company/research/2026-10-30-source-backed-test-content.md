## Deduplication and provenance

1. Start with the canonical source key: platform + repository/community + issue/post ID. Strip tracking parameters from the identity key while retaining an exact comment anchor when it supports a distinct claim. Redirects/aliases/crossposts do not by themselves create new incidents. Preserve meaningful URL components; do not merge every similarly titled post.
2. Compare existing accepted summaries before adding another: same upstream incident/trigger/environment is one finding with additional source links or context, not a new finding for every comment, persona or failed attempt. A GitHub issue and Reddit discussion linking to it normally belong to that same source cluster.
3. Keep distinct mechanisms separate even when error text matches. The retained MCP research distinguishes POST-response lifetime from standalone GET-retry exhaustion; that existing comparison is a dedupe caution, not a current claim that either issue is fixed/open. A different version alone is neither proof of a duplicate nor proof of a new root cause.
4. Preserve contradictory observations with their own source/conditions. Do not retain only a success comment or average contradictory outcomes into a global verdict. If the relationship is uncertain, hold the merge and explain the specific ambiguity; do not inflate the target with questionable duplicates.
5. The review ledger should link the proposed app record to its canonical source cluster, inspection date, curator/test persona, exact factual limitations and review disposition. After an approved write, add the actual app ID/URL; never fabricate one in preparation. Store no passwords, access tokens, account-session material or private operator identifiers here.

## Compact copy boundary

Recommended report prefix, adapted to the actual source rather than pasted as a claim of performed research:

> Synthetic application test content. This account curates an original summary of the linked public issue and is not its reporter. Versions, symptoms and any proposed remedy below are source-reported. Token Overflow's test operators have not locally reproduced or independently verified this issue.

Then state the actual sourced symptom/conditions, what remains unknown, source link and inspection date. Do not populate an unperformed local check or manufacture an exact change/after result. A source may contain empirical evidence from its own author; preserve that attribution without turning it into a test-operator verification.
